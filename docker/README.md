# SWAN docker image

This directory builds a Docker image that runs [SWAN](https://swanmodel.sourceforge.io/) on workspaces generated by rompy-swan. With it, you don't need to compile SWAN yourself.

The image is published as **`ghcr.io/rom-py/swan`**:

| Tag | Contents |
|---|---|
| `41.51` | SWAN release 41.51 |
| `latest` | The newest release |

Pin a version tag for reproducible runs, since `latest` moves when a new release is published. Every image is tested with workspaces generated by rompy-swan before it is published.

Each image contains SWAN built with NetCDF output (`BLOCK` and `SPECOUT` files ending in `.nc`), in two builds, plus the Open MPI runtime:

| Command | What runs |
|---|---|
| `swan.exe` | The MPI build when started by `mpirun` with 2 or more processes, the serial build otherwise |
| `swan-serial` | The serial build |
| `swan-mpi` | The MPI build |

SWAN reads the command file `INPUT` in the working directory, which is what rompy-swan writes.

> [!NOTE]
> The official image from the SWAN team, `delftwaves/swan`, is built without NetCDF, so it writes `.nc` output files as text.

## Running a generated workspace

### From rompy-swan

Use rompy's Docker backend:

```python
from rompy.backends import DockerConfig

modelrun.run(DockerConfig(image="ghcr.io/rom-py/swan:41.51", executable="swan.exe"))
```

To run with MPI across 4 processes:

```python
modelrun.run(
    DockerConfig(
        image="ghcr.io/rom-py/swan:41.51",
        executable="swan.exe",
        mpiexec="mpirun",
        cpu=4,
    )
)
```

With MPI, SWAN writes one `PRINT` file per process (`PRINT-001`, ...).

### From the command line

Run these commands from inside the workspace directory:

```bash
docker run --rm -v "$PWD":/data ghcr.io/rom-py/swan:41.51 swan.exe
docker run --rm -v "$PWD":/data ghcr.io/rom-py/swan:41.51 mpirun -n 4 swan.exe
```

> [!NOTE]
> The container runs as root, so SWAN output files in the workspace are owned by root. On Linux, add `--user "$(id -u):$(id -g)"` to `docker run` to keep your own ownership.

## Building locally

Build a release from its source tarball, giving the version and the checksum listed in `releases.txt`:

```bash
docker build -t swan:41.51 \
  --build-arg SWAN_VERSION=41.51 \
  --build-arg SWAN_SHA256=325c229f3dde0b812db4ec9ae6fa1cd4086d2109562c389576590ce8f94b26bb \
  docker
```

To check that an image runs rompy-swan workspaces (stationary, nonstationary and MPI):

```bash
python docker/test_image.py swan:41.51
```

## Publishing a new release

Add a line to `releases.txt` with the version and the SHA-256 checksum of its tarball, then merge to `main`. The `SWAN docker image` workflow builds, tests and publishes it, and moves `latest` to the last release in the file.
